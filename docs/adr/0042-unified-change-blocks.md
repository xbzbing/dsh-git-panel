# ADR-0042：统一差异按连续变更块先删后增，增删底色覆盖整块

- 状态：Accepted（2026-11-26）
- 相关：issue #156、ADR-0016、ADR-0043、`src/client/diff.ts`、`src/client/DiffView.tsx`、`src/client/css/diff.ts`

## Context

Git 的 unified patch 在每个连续变更块内先列删除行，再列新增行；上下文行与 hunk 表头划分块。面板为 split 视图把连续删除与新增按位置配成 `mod` 行，再生成 unified 列表。逐个拆开 `mod` 会把整段重写呈现为一删一增的交错序列，读者难以连贯阅读旧代码与新代码。

行号若保持中性灰底，块的首尾只能靠代码列的颜色判断，长行和空白格尤其难定位。备选方案：只给代码着色（改动最小，但边界缩到文字起点）、给整行加 `border-left`（会挤动列宽，且虚拟窗口的行是扁平网格、没有行元素）、给每个格子都加边缘色条（行号与符号列会出现几条相隔十几像素的竖条，像多列色轨）。选择整行底色加代码列一条 2px 内阴影：不改布局，且每行只有一个块边界。

## Decision

1. unified 列表把连续 `mod` / `del` / `add` 视为一个变更块：按旧侧原序输出所有删除，再按新侧原序输出所有新增；context、hunk、gap、meta 终止块，文件末尾也必须输出待处理的新增。不跨边界合并，不改变 split 的位置配对、侧别、行号或文本。
2. 增删底色覆盖整块：unified 的两列行号（含空白格）、符号列与代码同色；split 仅对应的增删侧着色，对侧空白格与 before / after 视图保持中性。边缘色条只由代码格承担——split 每侧一条、unified 一条，都落在代码列左缘；行号与符号列只继承底色，不复制色条。
3. 增删规则只设 `background-color` 与这一条内阴影，不以 `background` 简写清掉其他图层。行号悬停与评论选中用 business 色背景图层叠加，选中层优先于悬停层，键盘焦点轮廓仍可见。
4. 保留每行已有的词级强调范围（[ADR-0043](0043-word-emphasis-heuristic.md)），unified 重排只改变显示次序。评论选区以 side + 行号标识，引用仍来自原始 patch；查找与虚拟窗口以当前显示列表为准，不以旧显示下标标识代码。
5. 所有处理保持线性时间，无 LCS 矩阵、无大行的码点数组、无新的 host 查询或 wire 契约。

## Consequences

- 连续重写可按旧块、新块阅读；多行块的新增会显示在该块最后一条删除之后。单行替换、纯新增、纯删除保持原有阅读方式。
- 每条变更行只有代码列一条 2px 色条，与代码起点对齐；行号与符号列只继承底色，不会被平行色条切成色轨。
- 回归需覆盖增删行数不等、上下文与 hunk / gap / meta 边界、文件末尾输出、行号 / 符号 / 代码同色与色条归属，并在隔离浏览器中核验叠层、模式切换与查找。
- 词级强调是同一 issue 的另一项独立决策，见 ADR-0043；两者可以分别推翻。
- 后续若要把变更块折叠、默认展开或按近似对齐重排，需另写 ADR；不能为了视觉对齐静默修改 Git 的上下文、行号或评论引用。

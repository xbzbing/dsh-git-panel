# ADR-0042：统一差异按连续变更块先删后增，词级强调采用保守启发式

- 状态：Accepted（2026-11-26）
- 相关：issue #156、ADR-0016、ADR-0039、`src/client/diff.ts`、`src/client/DiffView.tsx`

## Context

Git 的 unified patch 在每个连续变更块内先列删除行，再列新增行；上下文行与 hunk 表头划分块。面板为 split 视图把连续删除与新增按位置配成 `mod` 行，再生成 unified 列表。逐个拆开 `mod` 会把整段重写呈现为一删一增的交错序列，读者难以连贯阅读旧代码与新代码。

按位置配对不代表代码具有语义对应关系。旧的词级强调仅去除公共前缀和后缀；无关行经常共享缩进、括号或测试包装，剩下几乎整行被强调，与增删底色重复。

备选方案包括：只在增删行数相等时强调（简单，但不能排除等长块中的无关行，并会遗漏不等长块中的小编辑）；按相似度配对或为块执行字符级 LCS / Myers（可改善对齐，但需要预算控制和新的范围模型）。当前修复不重算 Git 的行级 diff，也不引入依赖。

## Decision

1. unified 列表把连续 `mod` / `del` / `add` 视为一个变更块：按旧侧原序输出所有删除，再按新侧原序输出所有新增；context、hunk、gap、meta 终止块，文件末尾也必须输出待处理的新增。不跨边界合并，不改变 split 的位置配对、侧别、行号或文本。增删底色延伸至行号：unified 的两列行号（含空白格）与正负号、代码同色；split 仅对应的增删侧着色，对侧空白格与 before / after 视图保持中性。评论选中底色与键盘焦点优先于行号的增删底色，不重复复制代码侧的边缘色条。
2. 词级强调仍使用公共前缀 / 后缀确定一个变化区间。若共享部分仅有空白，则不强调；若变化区间覆盖两侧各自内容的比例都严格大于 60%，也不强调。比例按 Unicode 码点计算，排除行首 / 行尾空白；区间坐标仍为 UTF-16，不能切开代理对。60% 是保守的显示启发式，不是语义相似度保证；一侧仍大部分不变的插入、删除或小修改继续强调。
3. 保留每行已有的强调范围，unified 重排只改变显示次序。评论选区以 side + 行号标识，引用仍来自原始 patch；查找与虚拟窗口以当前显示列表为准，不以旧显示下标标识代码。
4. 所有处理保持线性时间，无 LCS 矩阵、无大行的码点数组、无新的 host 查询或 wire 契约。

## Consequences

- 连续重写可按旧块、新块阅读；多行块的新增会显示在该块最后一条删除之后。单行替换、纯新增、纯删除保持原有阅读方式。
- unified 与 split 都会减少低信息量的词级底色。启发式可能隐藏某些真实的大修改，也不能保证每对被强调的行都有语义关联；增删整行底色和文本始终保留，不影响 patch 内容。
- 回归需覆盖增删行数不等、上下文与 hunk / gap 边界、文件末尾输出、阈值边界、空白与 Unicode，并在隔离浏览器中核验行号、评论、模式切换与查找。
- 后续若仍有错配反馈，再评估有界的相似度配对或字符级块细化；不能为了视觉对齐静默修改 Git 的上下文、行号或评论引用。

# ADR-0026：变更列表的平铺 / 树形两种视图

- 状态：Accepted（2026-11-03）
- 相关：issue #99、`src/client/changes-tree.ts`、`src/client/ChangesTab.tsx`、`src/client/changes-rows.tsx`、`src/client/selection-keys.ts`、`src/host/parser.ts`（`parseStatus`）、ADR-0008 / 0012 / 0013 / 0016

## Context

变更页一直是平铺列表：一次改动跨多个目录（重构挪目录、批量生成页面）时，读者只能在一长串扁平路径里用眼睛找目标文件。issue #99 提出按目录层级折叠，并顺带提出几件事：目录节点汇总变更数、目录级暂存 / 放弃、按路径过滤、记住选择。

这条需求落进现有结构时有几个必须先回答的问题：

1. **树在哪里建？** 快照的 `changes` 是 `git status` 的平铺结果。让 host 分组会为同一个路径逻辑再写一份实现，还要改 wire 形状；而路径折树在 client 已有纯函数（`file-tree.ts`，提交详情的文件列表在用）。
2. **虚拟列表怎么办？** 变更列表按固定行高做窗口化（issue #16 的大仓库限流），行高是窗口数学的输入。多出一种行就得让高度表也认识它，且 CSS 必须钉同一个值。
3. **目录操作凭什么安全？** 「放弃」只删工作区文件（ADR-0008），未跟踪条目若本身是仓库要整批拒绝。目录级操作绝不能把「目录前缀」这种 host 没校验过的 argv 素材塞进请求。
4. **选择集怎么复用？** 选择键是 `path:s` / `path:w`（同一路径的两侧独立），组头已经有三态全选。
5. **视图选择存哪？** 配置字段（如 `defaultDiffView`）写入会触发 `resyncAll()` 重采样整个快照——为了切一个列表视图重跑一遍 git 不划算；而且这是「此刻想怎么看」，不是安装级偏好。

备选方案：

- **host 侧分组**：wire 多一份树结构，client 还要还原成行。不采用。
- **新开一个视图 / 页签**：行契约、工具栏、选择语义都要第二份。不采用。
- **视图模式进 host 配置**：写配置等于一次快照飞行，切换成本远高于收益；且配置是全安装共享，与「我这个浏览器此刻想看树」不是一件事。不采用。
- **目录放弃沿用行内的「再点一次」**：一个文件两击可接受，一棵子树两击太廉价。不采用。

## Decision

- **一个纯函数出两种行**：`changes-tree.ts` 的 `buildChangeRows` 把「组 → 行」拍平成一份列表，平铺与树形只是同一份数据的两种走法。行的种类是 `head` / `dir` / `file`，`ChangesTab` 只做「种类 → 高度、徽标、回调」的映射。目录树复用 `file-tree.ts`（同目录先于文件排序、单子目录链折成 `src/client` 一行）。
- **行高按种类钉死**：`head` 26 / `dir` 26 / `file` 28，CSS 用 `.gp-changes__vrow>…{height:100%}` 跟随同一组常量。新增行种类必须同时改两处，否则窗口数学与渲染会错位。
- **折叠状态按「组 + 目录路径」记**：`dirKey(group, path)`。同一目录在「已暂存」与「更改」各有一行，两处独立折叠；切换仓库（`snapshot.root` 变化）时清空，避免旧检出留下的路径把新树的一层藏起来。折叠状态不持久化——只有视图模式持久化。
- **目录的挑选复用组头全选**：目录行带 `changes`（其后代变更条目），三态勾选与「选择本组全部文件」是同一段 `selection-keys` 逻辑，没有第二套选择语义。折叠起来的目录照样能勾选其后代。
- **目录级操作只报它自己那些行**：`dirStageAction` 取该组这一侧的路径（已暂存 → 取消暂存，工作区 → 暂存），`dirDiscardPaths` 只取工作区侧。传的始终是「已经是变更条目」的路径，绝不传目录前缀，所以嵌套仓库 / 折叠未跟踪目录的既有拒绝（`nested-repo`）原样生效。
- **目录放弃走二次确认框**：复用批量放弃的对话框（同一套计数与未跟踪警示），标题点明作用域是哪个目录。行内的「再点一次」手势只留给单个文件。
- **过滤是纯客户端的路径子串匹配**（大小写不敏感），两种视图都生效。命中数成为组头与目录徽标的数；某组无命中就从列表里消失；全无命中显示「没有匹配的变更」而不是「没有未提交的变更」。**过滤只临时展开命中的祖先（组头与目录都算），不改折叠状态**：清空过滤后，读者折叠过的组与目录仍然是折叠的。
- **默认平铺**：已有用户的行为不变，树形是一次点击的距离。选择写在 `localStorage` 的 `gp.changes.view`（与列宽同一处，不进 host 配置）。
- **重命名带上源路径**：`GitChange.oldPath`（可选，旧 host 不提供即读不到）由 `parseStatus` 在 R/C 的那一侧填上；行内以 `← 旧路径` 展示，悬停标题写 `旧 → 新`。git 只在索引侧报告重命名，工作区的移动仍是「删除 + 未跟踪」两条。

## Consequences

- **被过滤掉的行可能仍在选择集里**（与组头全选同一语义：勾选的是行，不是视图）。暂存 / 提交作用于勾选的路径，即使它当前不在屏幕上；组头计数只报命中数，不会假装覆盖了整组。
- **目录徽标只数已加载的行**。列表被 host 截断时组头仍是统计里的诚实总数（ADR-0013），目录数是「现在能看到的这些」。两者口径不同是有意的：目录节点描述的是列表内容。
- **重命名展示依赖 host 支持**：旧 host 的快照没有 `oldPath`，客户端读不到就只显示新路径，不会崩。
- **行的缩进是内联 `padding-left`**（平铺 20px，树形每层 +14px）。这意味着后续任何按档位改行内边距的 CSS 都要考虑内联样式会赢；`.gp-dir-row` 的触屏「操作常显」规则必须和 `.gp-file-row__actions` 一起写进 `layout.ts` 的 `hover:none` 媒体查询。
- **过滤框常驻一行**（有变更时）。它让左栏少一个 30px 级的高度，与「窄且矮时藏东西」的约定不冲突：该行在 cramped 档不隐藏，只是控件用紧凑尺寸。
- **测试**：`test/unit/changes-tree.test.mjs`（折叠 / 过滤 / 目录目标 / 行序）、`test/unit/parser.test.mjs` 的重命名用例、`test/e2e/changes-tree.mjs`（视图切换与记忆、缩进、折叠、目录级暂存与放弃、过滤命中展开）。
- **本期不做**：目录级「批量取消跟踪」、树形下的拖拽、跨组共享折叠状态、过滤的模糊 / glob 匹配。目录前缀的重新分组也不做——它会让 host 的 `isSafePath` 之外多出一条路径解析权威。

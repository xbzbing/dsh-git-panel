# ADR-0014：AI 提交生成的语言、预算、自定义规范与提示词预览

- 状态：Accepted（2026-10-18，迁移自现有实现）
- 相关：[生成入口](../../src/host/suggest.ts)、[单源提示词构造](../../src/host/suggest-prompt.ts)、[查询入口](../../src/host/queries.ts)、[模型接口](../../src/host/llm-face.ts)、[生成回归](../../test/unit/suggest.test.mjs)、[提示词契约回归](../../test/unit/suggest-prompt.test.mjs)、[预览与草稿回归](../../test/unit/suggest-prompt-config.test.mjs)

## Context

「AI 生成提交信息」有三个容易做错的地方，每一个都有实测教训：

1. **语言**。界面语言不等于提交语言。中文界面的用户在英文仓库里工作，应该得到英文提交信息。更糟的是：仓库里如果有一批自动生成的英文提交（release / merge / revert），按「近期提交」推断会把结论翻成 `en`，即使作者本人一直写中文。
2. **模型解析时机**。`llm` 服务与默认模型如果写进 `static inject` 或在构造期冻结，用户在设置里换了模型不会生效。
3. **预算与截断**。压缩产物（minified bundle）里的超长行会吃光 token 预算，把真正有信息量的 diff 挤出去。

另外一条经验：**语言要求只写在 system 里不够**，模型仍会输出错误语言。

## Decision

- `llm` / `agentDefaultModel` **按请求解析**（`getLlm` / `getAgentDefaultModel`），不在构造期冻结、不进 `static inject`；模型路由 config 覆盖（provider/model 必须成对）优先，否则用 `agentDefaultModel.currentSelection()`。
- **语言默认 `auto`**：按仓库自身近期提交推断；**先滤掉机械提交**（release / merge / revert / `fixup!` / `squash!`），本人提交足够时只看本人；**不跟随界面语言**。
- **语言要求同时写进 system 和 user 消息末尾的独立 text block**，且该 block 位于 diff 截断预算之外。
- **diff 进预算前先折叠超长行**（压缩产物会吃光预算），但**结构性行一律不折**（`@@`、`diff --git`、`---`/`+++` 等承载 hunk 坐标）；**折叠不算截断**，不计入 ADR-0013 的截断标记。
- 配置面提供开关、生成语言、输入预算 / 输出上限 / 超时，范围与 host 实际执行范围从同一处派生（ADR-0002）。

### 自定义提交规范与透明预览

- **插件级 `suggestPrompt`** 为 volatile 字符串，缺失或纯空白使用内置默认；非空内容替换默认写作规范，而不是追加在旧规则之后。直接追加会让标题长度、禁止列表等旧要求继续压过用户规范。仓库历史仍作参考和 `auto` 语言投票，自定义格式优先。
- **格式与语言分离**：默认分支保持原指令；自定义分支允许无前缀、不同标题长度、列表和多段正文。两处语言提醒仅约束自然语言描述与正文，固定标记、ID、type、scope 由用户格式决定，不自行增加或翻译前缀。仅输出提交文本、输入数据不是指令的任务边界保留，模型请求不提供工具。
- **独立输入上限**：自定义规范最多 16 KiB UTF-8，不计入 diff 字节预算。此可选字段的入站 schema 保留异常值，不使用会在插件激活前拒绝整个配置的 string schema，也不以 schema 默认值把显式 null 改为空串；唯一的 `readSuggestPrompt` 验证阶段只接受有界字符串。超限或非字符串配置只阻断 `suggest`，不影响普通 Git 端点；不静默截断或退回默认。
- **预览文本上限**：输入规范保留 16 KiB UTF-8 上限，固定任务和语言指令单独预留 4 KiB；完整指令串上限为两者之和，由 host 类型常量单源提供，client 不以倍数猜测。单测钉住实际固定指令不超过预留预算，修改包裹文本时会在门禁中暴露越界。
- **同源查看**：`query` 的 `suggest-prompt` 分支在仓库解析前返回默认或当前已保存配置的中文／英文 system 与末尾提醒；真正生成使用相同纯构造器。默认查看独立于自定义配置有效性，两种查看都不读取 session/Git/fs，也不调用模型。设置页没有具体仓库上下文，`auto` 展示两个版本；不把动态 files/diff/历史样本的占位文本冒充完整模型请求。
- **保存与预览分离**：编辑只改草稿，显式保存；保存失败保留内容，清空草稿后保存才恢复默认。保存成功只显示已保存状态，不自动打开预览；「查看最终提示词」按需打开，并核对 host 返回的规范与语言设置以确认对应最近一次保存，迟到响应不得覆盖新结果。保存成功而预览读取失败分别提示，重试只查询。旧 host 未声明新字段时禁写，配置只读或生成关闭仍可查看默认。
- **披露边界**：规范由宿主设置服务保存，不直接重写 profile；生成会将自定义规范与 diff 一起交给所选模型供应商。预览只展示本插件的指令，不展示真实 diff、会话系统上下文或模型推理，不将整段规范加入周期性 Git 快照或日志。

## Consequences

- 中文用户的英文仓库得到英文提交信息；自动生成的英文提交不再污染语言推断。
- **自定义格式保真代价**：自定义分支只 trim 模型输出，不猜测围栏或末尾分隔线是传输包装还是用户要求的固定语法。提示词要求除非自定义规范明确要求，否则不附加围栏、引号或尾部分隔线；模型仍可能不遵循，生成结果需用户在提交框审阅。默认分支继续既有包裹清理，不能为减少意外包装而静默破坏自定义格式。
- 代价：`auto` 的推断逻辑本身需要维护（机械提交的过滤名单、本人提交的阈值），且有单测锁定。
- **请求构造单测不代表模型遵循率**：单测只能证明「语言要求写进了两个位置」，真实遵循率必须经官方适配器 + 真实模型验证。**禁止用手工重组的 HTTP 请求替代官方适配器验证**——那条路绕过了真实的请求组装，验证结果不成立。

# ADR-0026：历史文件 / 路径搜索采用受控 pathspec 与响应能力门控

- 状态：Accepted（2026-11-03）
- 相关：ADR-0002、ADR-0005、ADR-0010、ADR-0011、`src/host/types.ts`、`src/host/validate.ts`、`src/host/queries.ts`、`src/client/overview-hooks.ts`

## Context

Git 总览原有搜索只按提交消息或哈希工作。用户还需要查找历史上曾出现过的文件名和路径片段，包括已经删除的路径与目录片段；作者、日期和分支筛选应继续与搜索条件叠加。

路径搜索有几个边界需要固定：它不应变成代码内容搜索、正则搜索或用户自定义 glob；改名也不应隐式扩大为旧路径追踪。Git 的默认路径历史会为了路径相关性简化部分合并提交和支线，这与提交详情的完整文件列表属于不同口径，不能用详情查询反推搜索结果。

路径关键词来自 RPC，不能直接作为 Git pathspec。与此同时，旧 host 可能忽略新增请求字段，因此客户端必须确认每次成功路径查询确实由支持该能力的 host 完成，避免把消息搜索结果误显示为路径搜索结果。

备选方案都被否掉：**新增独立的历史文件查询端点**——会复制分页、作者 / 日期 / 分支过滤、取消和拓扑补查，成本高于扩展现有请求；**`--follow` 自动追踪改名**——只接受单个路径，与“文件名 + 目录片段”的多路径语义冲突，且历史遍历代价不可控；**`--full-history` / `--simplify-merges`**——结果偏离 Git 原生文件历史，提交图与总数的口径要一并重新定义；**搜索代码内容（`-S` / `-G`）**——需要逐提交计算 diff，是另一个资源档位，应单独立项评估；**客户端先按当前文件树筛选再查历史**——已删除路径会消失，且无法得到完整的历史命中数。

## Decision

在现有 `history` wire 请求中追加可选字段：

```ts
readonly pathSearch?: string
```

在 history 成功结果中追加能力标记：

```ts
readonly pathSearchSupported?: true
```

新 host 在所有 history 成功响应中声明 `pathSearchSupported: true`，包括无结果、空仓库和无匹配分支的成功返回。

host 对路径关键词执行文本约束、长度和互斥校验；非空 `search` 与非空 `pathSearch` 同时出现时返回既有 `invalid-name` 错误。长度上限作用于原始输入（trim 之前），空白输入按“未筛选”处理，互斥判断同样以 trim 后是否非空为准。路径模式下关键词按 Git 路径的字面子串匹配处理，英文大小写不敏感；文件名、中间目录名和带 `/` 的路径片段都可命中，不额外承诺所有 Unicode 大小写折叠一致。输入去除首尾空白，内部空格保留；空白关键词视为未筛选。非字符串、控制字符、NUL 及超过共享上限 `HISTORY_PATH_SEARCH_MAX_LENGTH = 1024`（JavaScript `string.length`）的输入拒绝。纯十六进制路径关键词不进入哈希跳转。

host 将经过转义的关键词放入唯一的 `--` 后 pathspec，固定构造为：

```text
:(top,icase)*<escapedKeyword>*
```

只转义 Git 默认 wildcard 语义中的反斜杠、星号、问号和方括号，不启用 glob magic。`git log` 与 `git rev-list --count` 使用完全相同的 pathspec、范围和既有过滤参数；不改变写操作的 literal pathspec 策略，也不添加 `--follow`、`--full-history`、`--simplify-merges` 或 `--first-parent`。

文件 / 路径模式不搜索代码内容；已删除路径可搜索；改名不会自动追溯仅存在于改名前的路径。作者、日期、分支筛选与路径条件按 AND 组合。提交详情继续使用原有完整文件列表、统计和 diff 口径，并遵守 ADR-0011，不因历史路径筛选隐藏未匹配文件。

client 通过成功 history 响应中的 `pathSearchSupported: true` 维护 unknown / supported / unsupported 三态。能力未知时文件 / 路径入口不可选；字段缺失时路径查询结果不得发布，保留旧结果并提示更新或重新加载 host。每一次路径搜索成功响应都再次校验能力字段；失败、过期或失效请求不能更新能力状态。远端重建时重置为 unknown。旧 client 忽略新响应字段，旧 host 仍可服务消息 / 哈希搜索。

## Consequences

- 路径搜索复用 history 端点、分页、作者 / 日期 / 分支过滤、超时、取消和有界拓扑补查，不增加新的 RPC 端点或后台索引。
- 路径筛选要逐提交比较树，而计数走完整段历史（列表有 `--max-count` 可提前停）；超大仓库上可能比消息搜索更早撞到既有超时，与既有作者 / 日期过滤同构，暂不单独放宽。
- Git 原生的路径历史简化会让部分普通合并和支线提交不出现在结果中；这是产品定义的一部分，界面用简短帮助文案说明，不承诺枚举所有相关父边。
- 受控 pathspec 保留目录片段与通配符字符的字面匹配，同时避免把用户输入解释为额外 pathspec magic 或选项。
- 新字段保持向后兼容，但旧 host 不会被静默当作支持路径搜索的 host；发布前必须覆盖新旧 host 组合、无结果成功响应和能力缺失响应。
- 若未来需要完整 merge 历史、改名追踪或代码内容搜索，应分别评估新的查询语义和资源上限，不在本决策中隐式扩展。

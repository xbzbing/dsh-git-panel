# ADR-0038：差异行内评论以引用写入输入框，格式对齐平台「本地变更」页签

- 状态：Accepted（2026-11-23）
- 相关：issue #123、ADR-0016、ADR-0028、`src/client/review-quote.ts`、`src/client/DiffReviewBar.tsx`、`src/client/review-view.ts`、`src/client/quote.ts`、`src/client/menu-proxy.ts`

## Context

issue #123 希望在差异里对选中的行写评论，再连同文件、修改前 / 后、行号、对比对象和代码片段交给当前会话的 Agent，支持单条与批量。讨论里维护者的意见是交互不必做重：飞书式的草稿箱要单独打磨，而「引用到输入框」只要小心别按到回车，且面板本来就不遮挡输入框。

dsh 0.2.3 带来了两件相关的平台能力：

- 可选 bundle「变更请求与工作树」（`@deepseek-ai/dsh-experimental-forge-bundle`）的右侧栏「本地变更」页签：选中差异行写评论，点「添加到输入框」后以原子引用写入草稿，正文是 `## User Comment N` + `File` / `Side` / `Lines` / `Source` / `Diff hunk` / `Comment`，编号按草稿里已有的同名标题顺延。它的客户端半提供 `ctx.forgeChanges.open(target, { path })`。
- 平台文件菜单的「添加到对话」（`reference.file/addToChat`）：往草稿插入一个 `@文件` 引用，不发送。

但「本地变更」页签只读**会话 cwd 所在的检出**，并且只有四种本地范围（branch / uncommitted / unstaged / staged）。本插件的差异还来自切换器里的嵌套仓库、worktree 和 `.code-workspace` 外部根，以及提交差异弹窗与「与修订版本比较」——这些平台都覆盖不到。bundle 默认也不启用。

## Decision

三件事一起做，各管一段：

1. **借用平台的「添加到对话」。** `FILE_VIEWS` 白名单加入 `reference.file/addToChat`，沿用 ADR-0028 的借用机制：标签、图标、可用性都是平台的，目标仍传绝对路径。平台写的是可解析的 `@文件` 引用，Agent 当文件读；插件自己的「引用到输入框」写的是纯文本路径，两者并列只是同一件事的两个答案，所以文件行上平台给出「添加到对话」时不再显示插件的那一项。这一判断放在借用组里做（`fileBorrowedActions`）：只有它看得到平台实际返回了什么；旧宿主或平台答复超出预算时，借用组末尾补回「引用到输入框」。目录行没有平台对应项，保持不变。

2. **在会话检出上把人引到平台页签。** 变更页的差异工具栏在两个条件同时成立时显示「在「本地变更」中审阅」：`forgeChanges` 服务存在，且面板选中的是默认仓库（仓库标签为 `''`，即会话 cwd 的检出）。按钮调用 `forgeChanges.open({ sessionId, source: { kind: 'local' } }, { path })`。服务按结构声明、用时探测，不 import 该包，也不写进 `dsh.client.inject`（ADR-0032：可选包缺席时不能挡住本插件加载）。

3. **本插件的所有文本差异都能评论，引用格式与平台逐项一致。**
   - **只在有输入框时开放。** Panel 用 `quoteAvailable` 判断；没有输入框时行号仍是普通数字，不会出现一个写完无处可去的评论框。
   - **选择规则**：鼠标停在一行上时行号旁显示「+」（与平台「本地变更」页签相同的提示，只对指针 hover 显示），点它或行号选一行；Shift+点击在同一侧、同一个 hunk 内扩展；跨 hunk、换侧或落在 hunk 之外都从被点的那一行重新开始。hunk 外（展开出来的上下文）只能单选，引用里写 `Code:` 块而不是 `Diff hunk:`。
   - **格式**：标题、字段名、字段顺序、范围标签（`R12` / `L3–5`）、`QuoteSummary`（`a.ts R4–6`）与平台一致；`Source:` 用平台的 `Local (scope)` 写法，commit 与 rev 分别补 `Commit:` / `Base:` 行。本插件额外写一行 `Repository: <绝对根>`，因为差异可能来自 cwd 以外的检出。编号读草稿里的 `## User Comment N`（含 `> ` 前缀），两边写进同一份草稿的评论连续编号。
   - **评论框放在滚动区之下，不插在行之间。** 差异主体是按索引测量行高的虚拟窗口（ADR-0016），行间插一个高度不定的表单会破坏窗口计算；放在下方还能在滚走选区后继续写，并且和输入框同在视野内。
   - **代码变化不重新指向。** 选中时冻结 hunk（或代码行）；差异刷新后若同一段文字不复存在，就取消选区高亮并提示「代码已经变化」，引用仍是选中时看到的代码，由用户决定是否添加。换文件则丢弃选区。
   - **失败不丢文字。** 输入框拒收时评论框保留原文并报错；Escape 只关闭评论框，不连带关闭外层弹窗；Ctrl/⌘+Enter 等同于「添加到输入框」。

## Consequences

- 批量发送靠输入框：多条评论攒在草稿里，一次发出就是一条消息。插件不保存草稿箱，也不区分「待发送 / 已发送」；平台页签里的评论记录与代码托管动作（GitHub / GitLab 评审）仍只在那边。
- 不支持编辑已经加入的评论：要改，就在输入框里删掉那条引用，重新写。
- 引用格式是一份跨仓库的约定。平台若改标题或字段，编号会各自从 1 开始、字段会不一致；`test/unit/review-quote.test.mjs` 与 `test/e2e/diff-review.mjs` 钉住的是本插件这一侧的文本，升级 dsh 时要对照平台的 `formatReviewComment` 复核。
- 「本地变更」入口只对默认仓库出现；切换到其他检出后入口消失，行内评论照常可用。

## 主要变更

- **重复挂载不再激活失败**：profile 里出现重复条目时（同一个包组合两次，或同一份代码来自不同安装来源），后到的挂载保持惰性并记一条警告，先注册的条目照常提供面板与 RPC；此前这种重复会以 `service "…" has been registered` 失败，在启动日志里留下一个永远 failed 的条目。
- **服务键与 wire 命名空间改为 `dbGitPanel`**：host 服务键、typert 命名空间与 client RPC / locale 命名空间统一到同一个常量，契约测试把两半钉在一起，通用名不再有机会撞车。**升级须知**：host 与 client 必须同版本；安装后重启 dsh 并硬刷新浏览器，旧 client 配新 host 会显示「Git 不可用」。详见 [ADR-0029](https://github.com/xbzbing/dsh-git-panel/blob/main/docs/adr/0029-unique-service-key-and-idempotent-mount.md)。
- **兼容表补上 `dsh@0.2.2-rc.1`**：安装、Git 面板、输入框标记、host RPC 与插件详情页在该版本上实测正常。
- **内部**：e2e runner 由 33 个合并为 31 个，改由并发池执行并按 CPU 收口，每个 runner 带超时；固定等待换成条件等待，场景模块直跑会显式失败，不再出现「跑完即绿」的假象。
- **内部**：CI 的 e2e 拆成独立 job（只跑 node 24）并复用 Playwright 缓存，命中时跳过浏览器安装；Chromium 守卫同时检查 headless shell。

## English

- **A duplicate mount no longer fails to activate**: when a profile composes the plugin twice, or the same code arrives from two install sources, the later mount stays inert and logs one warning while the first keeps serving the panel and the RPC; previously the duplicate failed activation with `service "…" has been registered` and left a permanently failed entry in the startup log.
- **The service key and wire namespace are now `dbGitPanel`**: the host service key, the typert namespace and the client RPC / locale namespace come from one constant, and a contract test pins the two halves together so a generic name cannot collide again. **Upgrade note**: host and client must be the same version; after installing, restart dsh and hard-refresh the browser — an old client bundle against the new host shows "Git unavailable". See [ADR-0029](https://github.com/xbzbing/dsh-git-panel/blob/main/docs/adr/0029-unique-service-key-and-idempotent-mount.md).
- **Compatibility**: `dsh@0.2.2-rc.1` joins the verified list — installation, the Git panel, the input-bar marker, host RPC and the plugin detail page all work normally there.
- **Internal**: 31 e2e runners (merged from 33) run through a concurrent pool capped by CPU, each with a timeout; fixed waits became condition waits, and a scenario module run directly now fails loudly instead of exiting green.
- **Internal**: the e2e job runs separately in CI (node 24 only) and reuses the Playwright cache, skipping the browser install on a hit; the Chromium guard also checks the headless shell.

## 主要变更

- **完成 Git Flow 时可以删除落后于本地的远端分支**：finish 的远端删除预检从「远端 tip 必须与本地完全相同」改为「远端 tip 是本地 flow 分支的祖先」。本地领先（开始 feature 默认推送之后最常见的完成状态）不再被误判成远端变化而整单拒绝；远端领先或分叉仍然拒绝并保留远端分支，删除继续使用 expected OID 与 lease，并在删除前复检（#149）
- **取消「删除远端分支」时不再残留本地分支**：`git branch -d` 会因上游仍落后而拒绝（即使分支已经合入目标分支）；host 现在先证明分支 tip 已在 HEAD 祖先链上，再补一次 `-D`，证明不了仍保留安全拒绝；squash 完成仍需在对话框里显式勾选强制删除（#149）
- **完成失败的提示按阶段区分**：预检阶段（还没有写入任何东西）提示「远端包含本地没有的提交，请先同步」；集成之后远端被并发推进时报 `flow-partial` 并说明是操作期间被改动；远端上游分支已被删除时提示取消删除该分支，或把分支推回远端（#149）
- **内部**：`merge-base --is-ancestor` 收敛为单一助手，只把 exit 1 判「非祖先」、其余非零走 git 错误；远端 tip 尚未 fetch 时先探测本地对象，不再被误报成领先或分叉（#149）

## English

- **Finishing a Git Flow branch can now delete a remote upstream that is behind local**: the finish precheck for remote deletion changed from "the remote tip must equal the local tip" to "the remote tip must be an ancestor of the local flow branch". A local branch that is ahead (the usual state after the start dialog publishes the branch and you keep committing) is no longer mistaken for a changed remote and rejected outright; a remote that is ahead or diverged is still refused and kept, and deletion still uses the expected OID plus a lease and rechecks the ref right before deleting (#149)
- **Keeping the remote branch no longer strands the local one**: `git branch -d` refuses when the upstream is behind even though the branch is already merged into the target; the host now proves the branch tip is on HEAD's ancestry and only then retries with `-D`, while an unprovable case keeps git's safe refusal. A squash finish still needs the explicit forced-delete acknowledgement in the dialog (#149)
- **Finish failures now say which stage they come from**: a precheck refusal (nothing written yet) says the remote has commits the local branch lacks, so sync first; a remote that moved after the integration reports `flow-partial` and says it changed while the operation was running; an upstream branch already deleted on the server asks you to uncheck the remote delete or push the branch back (#149)
- **Internal**: `merge-base --is-ancestor` now goes through one helper that treats only exit 1 as "not an ancestor" and routes anything else to a git error; a remote tip that has not been fetched yet is probed for locally first, so it is no longer misreported as ahead or diverged (#149)

## 主要变更

- **分支右键可删除本地分支**：Git 总览的本地分支行新增「删除分支…」，确认后先执行 git 的安全删除（`-d`）；分支上还有未合并提交时，确认框升级为强制阶段，勾选「我已了解」后才会发送 `-D`。当前检出的分支与标签行不提供该入口（#112）。
- **远端分支可从面板删除**：远端分支行新增「删除远程分支…」，必须勾选确认——服务端没有「未合并」保护，这道勾选是唯一的闸门。执行按已配置的 remote 解析（远端名可含 `/`）、目标固定为 `refs/heads/<branch>`，只删远端引用，本地同名分支与提交不受影响；服务端拒绝会原样显示原因。
- **修复**：标签行复用分支行渲染，此前右键会出现点了无反应的「切换到此分支」；分支专属项（切换、删除）现在按行类型关闭。
- **内部**：快照新增 `branchDelete` / `remoteBranchDelete` 能力位，旧 host 上不显示删除入口；菜单门控行携带的 `isTag` / `ref` 区分标签行与远端行。测试补齐本地两段确认、远端勾选解锁与 bare remote 真删夹具。

## English

- **Delete a local branch from its context menu**: the Git overview's local branch rows offer "Delete branch…"; the confirm runs git's safe delete (`-d`) first, and when the branch still has unmerged commits the dialog switches to its forced step, where the acknowledgement must be ticked before `-D` is sent. The checked-out branch and tag rows offer no such entry (#112).
- **Delete a remote branch from the panel**: remote rows offer "Delete remote branch…" and the confirm always requires the tick — a server has no "unmerged" safety net, so that tick is the only gate. The remote is resolved from the configured remotes (a remote name may contain `/`) and the target is always `refs/heads/<branch>`, so only the remote is touched: a local branch of the same name and its commits stay, and a server-side refusal is shown as-is.
- **Fix**: tag rows render through the branch-row component, so right-clicking one used to offer a "Switch to this branch" entry that did nothing; the branch-only entries (switch, delete) are now gated by the row type.
- **Internal**: the snapshot gained `branchDelete` / `remoteBranchDelete` capabilities (no delete entry on an older host), and the menu gates read the row's `isTag` / `ref` to tell tags and remote rows apart. Tests add the two-stage local flow, the remote acknowledgement flow and a bare-remote deletion fixture.

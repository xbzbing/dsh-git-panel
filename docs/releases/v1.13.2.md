## 主要变更

- **分支与提交右键新增创建 / 合并 / 拣选**：分支行可「从该分支创建分支…」（只创建、不切换，空名禁用确认、重名提示「分支已存在」）与「将该分支合并到当前分支…」；提交行可「在此提交创建分支…」与「将该提交拣选到当前分支…」。远端分支行按完整 tracking 引用操作，标签行不出这些入口，游离 HEAD 上不出合并与拣选（#118）。
- **冲突自动恢复**：合并或拣选遇到冲突会立即 `--abort` 恢复到操作前状态并明确提示（与既有还原一致），共享工作区不再被留在半途中；中止失败才提示「仓库仍处于操作中」。空拣选（改动已在当前分支）同样清理状态并单独说明。
- **内部**：快照新增 `branchCreate` / `branchMerge` / `cherryPick` 能力位（旧 host 不显示入口），新增 merge / pick 菜单图标与 8 语言 23 个文案键；测试补计划与菜单门控、真实 git 集成（建分支不动 HEAD、快进合并、冲突回滚无 `MERGE_HEAD` 残留、拣选成功 / 冲突 / 空 / 合并提交四种结局）与三套对话框 e2e 流程（#119）。

## English

- **Create, merge and cherry-pick from the context menu**: branch rows offer "Create branch from this branch…" (creates without switching; confirm stays disabled on an empty name and a duplicate reports "A branch with that name already exists") and "Merge this branch into the current branch…"; commit rows offer "Create branch at this commit…" and "Cherry-pick this commit onto the current branch…". Remote rows act through their full tracking ref, tag rows offer none of these entries, and a detached HEAD gets neither merge nor pick (#118).
- **Conflicts restore themselves**: a conflicting merge or cherry-pick is aborted immediately with `--abort` back to the pre-operation state and says so (same contract as revert), instead of leaving the shared work tree mid-sequence; only a failed abort reports "the repository is still mid-operation". An empty cherry-pick (its change is already in the current branch) is cleaned up the same way with its own message.
- **Internal**: the snapshot gained `branchCreate` / `branchMerge` / `cherryPick` capabilities (no entries on an older host), the menus gained merge / pick glyphs, and 23 new copy keys landed in all 8 languages; tests add the plans and menu gates, real-git integration (creating moves no HEAD, fast-forward merging, conflict rollback with no `MERGE_HEAD` left behind, and all four cherry-pick outcomes) and three end-to-end dialog flows in the `context-menu` e2e (#119).

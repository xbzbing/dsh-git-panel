## 主要变更

- **高频操作不再二次确认**：快进拉取、快进推送（两个入口）和干净工作树下的切分支现在直接执行，不再弹确认；host 端 `--ff-only`、不 force、分叉即拒绝的约束不变。操作发起后才失败时，错误按发起时的仓库归属显示在状态栏或内联横幅，脏树切分支仍保留 stash 确认（#109）
- **修复文件预览栏的闪断**：切换文件、预览还在读取时，工具栏继续沿用已落地文件的形态，模式切换、编辑入口和内容操作不再闪一下消失；读取在途时点全屏、JS 开关或属性，也不会作用到尚未上屏的下一个文件
- **内部**：pull / push / 切分支 / fetch 四条直连路径统一走 `op-runner` 的共享信封，同任务第二次按下由 ref 守卫丢弃，busy 生命周期与错误归属收敛成一份，`OverviewTab` 净减约 60 行（#110）

## English

- **No more second confirmation on common operations**: fast-forward pull, fast-forward push (both entry points), and switching branches on a clean worktree now run immediately. The host-side constraints are unchanged — `--ff-only`, never force, and refuse when diverged; when an operation fails after it starts, the error is reported against the repository it came from in the status bar or an inline banner, while switching with a dirty worktree still asks for the stash confirmation (#109)
- **Fix the file preview bar flicker**: while the next file is still being read, the toolbar keeps the shape of the file already on screen, so the mode switch, edit entry, and content actions no longer blink out; pressing fullscreen, the JS toggle, or properties mid-read does not act on a file that has not landed yet
- **Internal**: the four direct paths — pull / push / branch switch / fetch — now share `op-runner`'s envelope; a second press of the same task is dropped by the ref guard, and the busy lifecycle and error attribution live in one place, cutting about 60 lines from `OverviewTab` (#110)

- Keeping the preview bar's shape: reverting the toolbar to the loading-state `file` instead of the settled `barFile` turns the "the toolbar does not flicker while a read is in flight" assertion in `files-bar-review` red

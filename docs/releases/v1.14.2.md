## 主要变更

- **`.code-workspace` 多仓库不再靠猜**：会话目录里有工作区文件时，仓库切换器顶部（工作目录不是仓库时落在文件浏览的通知条）就地提示并给出一键开启；**存储库**区多了三态控件「关闭 / 自动发现 / 指定文件名」，设置仍默认关闭，写后立即重取列表。识别状态现在都有说法：找不到、无法自动选择、解析出来一个仓库都没有，各说各的。README 的「多仓库与工作区文件」与八份详情页同步说明了这套配置（[#125](https://github.com/xbzbing/dsh-git-panel/issues/125)）
- **工作区外的 worktree 现在能直接切换**：可选性改由身份判定——目录的 `.git` 必须回指本仓库的 `git-common-dir`（主工作树回指 common dir 本身，linked 回指 `worktrees/<id>`）。`git worktree list` 只是回放记录，手写 `gitdir` 或 `cp -R` / 解包出来的副本不会再被当成自己的 checkout；列表行与选择门用同一集合决定，未认证的行标为不可选（[#125](https://github.com/xbzbing/dsh-git-panel/issues/125)）
- **存储库列表上限可配置**：设置里可把上限设为 10–100（默认 50），改完立即重取；`.code-workspace` 带来的外部根上限从 20 提到 50，不占扫描的名额（#128）
- **工作区文件用不了时说清是哪一项检查拒绝的**：名字不合法 / 软链指向目录外 / 同名目录占位 / 文件过大 / 读不出来 / 内容不是工作区文件，六种原因各自出话并点名文件。以前它们共用一句「名称不合法，或链接指向目录外」，最常见的内容解析失败（`folders` 某项缺 `path`）反而被引去查文件名和软链（#127）

## English

- **`.code-workspace` multi-root repositories stop being guesswork**: when the session directory holds a workspace file, the switcher says so in place (in the file browser's notice bar when the working directory is not a repository) and offers a one-click switch; the **Repositories** section gains a three-state control — off / auto-detect / a specific file name — still off by default, and the list is refetched right after the write. Every recognition state now has something to say: not found, cannot choose automatically, or parsed with no repository in it. The README section "Multiple repositories and `.code-workspace`" and all eight detail pages describe the setting ([#125](https://github.com/xbzbing/dsh-git-panel/issues/125))
- **Worktrees outside the workspace are now switchable**: selectability follows identity — the directory's `.git` has to point back at this repository's `git-common-dir` (the primary work tree back at the common dir itself, a linked one at `worktrees/<id>`). `git worktree list` only replays a record, so a hand-written `gitdir` or a `cp -R` / untarred copy no longer passes as this repository's checkout; the row and the gate decide from the same set, and an uncertified row is marked unselectable ([#125](https://github.com/xbzbing/dsh-git-panel/issues/125))
- **The repository list ceiling is configurable**: set it to 10–100 (50 by default) and the list refetches immediately; the external-root ceiling a `.code-workspace` file contributes went from 20 to 50, outside the scan's budget (#128)
- **An unusable workspace file now names the check that refused it**: a malformed setting, a symlink out of the directory, a directory in the file's place, a file too large, an unreadable file, or content that is not a workspace file — six reasons with their own wording, each naming the file. They used to share one sentence, "malformed name, or a link out of the directory", which pointed the most common failure (a `folders` entry without `path`) at the wrong thing (#127)

- Certification regression: putting `isOwnCheckout` back to "a row in `git worktree list` is enough" turns "a record naming another repository is not certified" and "a copied repository does not inherit the original checkouts" in `repos` red
- Reason regression: making `scanCodeWorkspace` answer `invalid` without `reason` turns the reason assertions in `code-workspace` and the mapping cases in `workspace-hint` red
